# YT Cluster 1.20.11

Published 2026-11-05. deb `yt-cluster` 1.20 (build 1.20.11), EL9 rpm 1.20.11, tgz 1.20.11,
Docker image `dbinvent/yt:1.20.11`. ytserv 1.20.11.

## Upgrade

- Settings that held `key=value` text are now one row per setting (see Changed). The old
  C rows `sge_config`, `etcd_upsert`, `otel_headers` and `databases` are refused; after an
  upgrade ytserv ignores them and raises a warning alert. Write the new rows before you
  restart the nodes.

## New

- **S3 offload of blobs** (`bytea` columns of synced tables), off until set up. Each column
  gets a mode in the `blob` field of its table's config row (module `A`):
  - `sync`: the default, as before;
  - `copy`: the blob stays in the database; the origin uploads it after commit, a leader
    takes over if needed, and the synced table `yt_s3_blob` tracks it;
  - `move`: uploaded inside the transaction; the statement waits for S3's ack, and the
    column keeps NULL, or one zero byte if NOT NULL;
  - `quick`: as `move`, but sent after commit, so a committed blob is lost if the node
    dies first.
- S3 store settings are module `B` rows: `endpoint`, `bucket`, `region`, `secret`,
  `tmp_dir`, `tmp_limit_mb` and `tickets`, in the catalog or in a users database for its
  own store. The access keys come only from the secret store (`skv_secrets` on, value
  `access:secret`). Object key: `<database>/<schema>/<table>/<column>/<pk>`. A backfill
  sends existing rows. Tickets go to an etcd queue once `tickets` is set. Status in
  `yt_info('E')` row `s3`.
- Extension functions `yt_s3_blob()` (a BEFORE row trigger) and `yt_s3_probe(text)`,
  revoked from PUBLIC. Partitioned tables are refused. The ytctl TUI table editor has a
  `blob` field.
- **Schema plan and snapshot compare:** a `yt:plan` or `yt:snapshot` row asks every node for
  its `sge plan` output or schema snapshot (cluster tables left out). The origin keeps each
  node's text in `<history>_check` (the last 20 checks), and the row ends `yt:same` or
  `yt:differs <nodes>`; a node that does not answer is named, never counted the same. It
  applies nothing, does not stop a roll, and its result also goes to `sge_notify_queue`.

## Changed

- Settings in config modules, one row per setting:
  - `B`: S3;
  - `M`: sge settings (was `sge_config`);
  - `U`: databases (was `databases`): `*`, `<name>` = list, skip, detach or a table, and
    `<name>@<uuid>` for one node;
  - `F`: feeds `feed.<event>` (was `etcd_upsert`), `otel.<header>` (was `otel_headers`),
    and `recon.chunk`, `recon.mode`, `recon.col`, `recon.period`, `recon.attempts`;
    `recon_run` now names only the table.
- Module rows are checked at the statement that writes them and read within 2 s. Renaming
  a row is refused: delete it and insert. `yt_info('H')`, `yt_info('D')` and the
  `yt_help_with_defaults` view list rows by module and name. ytctl `--db-remove`,
  `--discovery` and the TUI write the new rows.
- `otel.*` rows replicate to every node; use `otel.<header>@<uuid>` for one node.
  `recon.mode` stays set until its row is deleted.
- A transaction that rolled a savepoint back over a write it sent to the cluster now fails
  at `COMMIT`, `yt_complete(true)` or `PREPARE TRANSACTION` with SQLSTATE `0A000`, and is
  on no node. This includes a PL/pgSQL `EXCEPTION` block. Retry it without the rollback.
  A savepoint rolled back over no write commits as before.
- The message size limit between nodes is raised, so rows with large `bytea` values
  replicate (tested to 10 MB).

## Fixed

- **Severe:** `BEGIN; SAVEPOINT a; INSERT 1; ROLLBACK TO a; INSERT 2; COMMIT` left the
  origin with row 2 and every member with rows 1 and 2, while COMMIT reported success.
- **Warning:** a forever spare's embedded rppd still opened queue watchers, so a message
  etcd handed it was lost when its writes were refused. It now opens none.
- **Low:** the extension could keep a stale prepared transaction id after a transaction that
  aborted or wrote nothing.
- On a spare, the etcd feed took a feed's queue and retried it forever. A bad feed row now
  stops only its own route.

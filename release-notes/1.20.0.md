# YT Cluster 1.20.0

Published 2026-10-21. deb `yt-cluster` 1.20 (build 1.20.0), EL9 rpm 1.20.0. ytserv 1.20.0:
from this release ytserv's version equals the package's (before, ytserv 1.2.0 was inside
deb 1.19.0).

## New

- **Two server builds.** `ytserv` has no Python in it; `ytserv-py` has rppd built in for
  Python functions and needs libpython. `ytctl --python` installs `ytserv-py`, and the setup
  wizard picks the build that matches. Both ship in the deb (glibc and musl variants, the
  pg18 variant too) and in the EL9 rpm.
- Setting `etcd_upsert` (cluster scope, empty by default, so off):
  `<event>=<schema.table>:<col>[,<col>]`, several separated by `;` or new lines. A JSON
  value put on that etcd queue or key prefix is upserted into the table on the named key
  columns, one cluster transaction per value. Queue routes consume on every node, prefix
  routes on the leader only. A failed value is retried with a backoff of 1 s up to 60 s; a
  value PostgreSQL refuses as it is (not JSON, SQLSTATE class 22 or 23) is rolled back,
  logged and acknowledged. The routes show in `yt_info('E')` as `etcd_upsert`.

## Changed

- The regular `ytserv` has no rppd and no Python; it warns when `serve_rppd` is on and
  points to ytserv-py.
- The regular ytserv and its own crates build with unsafe code forbidden, and its dependency
  audit is clean.
- marg (the argument parser) removes `SECRET` from the environment itself and prints a
  "Provided by DBinvent" line after its version line.

## Fixed

- On a sharded table, a write that reached the leader without its rows (a shard the leader
  does not hold) left a gap that made the leader refuse writes to every synced table with
  40001 until a pull closed it. Now only the tables that write named wait.

## Bundled

- The Schema Guard library, which ytserv applies schema with, takes Flyway file names as
  they are (`V1_2__name.sql`, and `R__name.sql` repeatables). Its dependencies moved to
  clap 4 and current semver, base64 and uuid.

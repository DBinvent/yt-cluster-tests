# YT Cluster 1.20.1

Published 2026-10-22. deb `yt-cluster` 1.20 (build 1.20.1), EL9 rpm 1.20.1. ytserv 1.20.1.

## New

- A running database can move into the cluster, and back out to plain PostgreSQL, with no
  downtime: node by node, each new node from a dump of the previous member, while the
  application keeps writing. 1.20.1 is the first version the join steps work on (the fixes
  below).

## Changed

- The deb depends on binutils and the rpm requires it: `ytctl --batch` reads each binary's
  glibc need with objdump to pick the variant, and without it found no ytserv ("Suitable
  ytserv binary version is not found").

## Fixed

- A node added at runtime (its `N` row written on the leader) counted toward the commit
  quorum before it ever answered, so a one-node leader refused writes as "not enough working
  nodes". The new node is now Spare, outside the count, until it answers.
- A joining node that stopped answering was marked Down and still counted in the party, so
  writes on the other nodes failed during the join. A joining node (Spare or Unconfirmed)
  is no longer demoted to Down.
- A joining node that reported itself Na or Down was recorded as Good and pulled into
  commits. It stays Spare until it reports a real state.
- A joining node could be refused admission for good ("older than this leader remembers")
  when the subterm it named was closed by another node. The leader now ages a position by
  the close at or below it, in admission and in auto-demotion.

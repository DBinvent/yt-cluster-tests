# YT Cluster 1.20.2

Published 2026-10-25. deb `yt-cluster` 1.20 (build 1.20.2), EL9 rpm 1.20.2, and for the
first time a tgz (1.20.2) and the Docker image `dbinvent/yt:1.20.2`. ytserv 1.20.2.

The Jepsen round of 2026-10-22 to 24 is in this release: its findings are fixed here.

## New

- **Docker image `dbinvent/yt`:** PostgreSQL with the extension and ytserv in one container;
  ytserv talks to PostgreSQL over its unix socket. Peers and cluster come from the
  environment (`YT_PEERS`, `YT_CLUSTER`, plus `POSTGRES_PASSWORD`, `POSTGRES_DB`). ytctl is
  in the image, but the setup does not need it.
- **tgz** of the static (musl) binaries, published with the deb and rpm
  (`<name>-<x.y.z>-<sha8>.tar.gz`, and a `-latest` link).
- Session setting `yt_cluster.delta` (off by default): a session whose statements are
  deltas sets it on, and a 55409 refusal becomes a 40001 retry.
- ytctl TUI:
  - each node's state, term, health and alerts (from `yt_info('e')`) on the monitoring
    screen, the cluster list and the node details;
  - Topology screen (`o`): the roster (`N` rows) and zones (`Z` rows), read from the
    leader. Add or retire a node, add or delete a zone, set its tier, level and host, and
    get the `--link-upper` command. A joins panel lists pending joins (`J` rows) and
    approves one on the leader (`A`);
  - provisioning (`P`) sets a node up with its roster: the peers file,
    `ytctl --batch --peers --cluster`, then the node's `N` row on the leader, after a check
    that its host resolves. It installs PostgreSQL when missing, copies the roles and the
    synced tables' schema from the leader, can write a PgBouncer ini, and compares the
    tables after the join;
  - an add-node wizard in five steps: SSH, PostgreSQL, apt repository, PgBouncer, review;
  - node info (`i`): `yt_info('E')`, `yt_info('r')` and the node's `C` rows;
  - data diff (`D`): compares a table across the nodes by key and writes a repair SQL file
    per divergent node, applied after a confirm.
- The ytctl setup wizard lets you pick the tables to put on the cluster; tables without a
  primary key are skipped.

## Changed

- A concurrent write that cannot be merged (a plain update) now fails with 55409 "refused,
  do not retry; review the row" instead of a 40001 retry that would overwrite the other
  write unreviewed. Writes the table's merge settings allow (increments, JSON documents,
  text) still get 40001.
- Commit mode `all` means every node online. Down, Spare, Paused and Unconfirmed nodes take
  no slot in the party, and writes are refused when fewer than a majority of the nodes are
  online. A node back from a restart goes Spare, then follower, with no operator step.
- A node behind the others refuses writes with 40001 ("behind, catching up - retry the
  transaction") until it has caught up, after a restart too; a write to a table this node
  is still catching up on is refused the same way.
- ytctl and the Docker image set `min_cluster_size` to a majority of the nodes.
- Party sessions on the members run with `application_name` `yt-party:<id>`, and apply
  sessions with a lock timeout instead of waiting on a row lock without end.
- A failed election logs its votes and each refusal.
- ytctl TUI puts a table on the cluster with `yt_setup` instead of its own triggers. It
  drops its older triggers, refuses a LIKE pattern that matches more tables than meant, and
  needs a primary key. Its table config save checks each field, keeps the settings the
  editor does not show (the shard config), and writes on the leader when the config table
  is synced, on every node otherwise.
- ytctl's node registry has a PostgreSQL port field, encodes special characters of user,
  password and database in the URL, and brackets IPv6 hosts.

## Fixed

- **Severe:** an insert of one key could commit although every party member refused it,
  leaving two values of the key on different nodes. Found by Jepsen.
- **Severe:** a committed write was dropped on a node that had rolled back its own part, and
  the copies never converged. Found by Jepsen.
- **Severe:** a node restarted under sequential consistency and `all` caught up only part of
  the writes it missed, out of order, and its copy stayed different. Found by Jepsen.
- **Severe:** a node could read itself caught up while it lacked writes: an insert cut off
  mid-write left an empty record that counted as held. Found by Jepsen.
- **Severe:** orphaned party sessions and lock waits across nodes could leave rows
  unwritable until a restart. ytserv now ends a party session its origin has decided and
  yields one that blocks.
- **Severe:** after a restart the data version starts at the oldest open term whatever the
  WAL file order, so a hole in an older term is not missed. A term with two WAL files keeps
  the bigger one and renames the other `.wal.dup`. Found by Jepsen.
- **Severe:** a subterm whose WAL record cannot be read in full is served as its outcome
  alone, never as part of its statements. Found by Jepsen.
- **Severe:** a copied node keeps its start position across a restart. Found by Jepsen.
- **Warning:** under `half` commits a row that diverged kept taking writes, and the
  difference grew. A row found divergent is now blocked on the whole cluster (55000) until
  recon repairs it from a majority. Found by Jepsen.
- **Warning:** after kills and a partition, the leader of an older term led on and restarted
  members stayed Spare behind it, so the cluster had no agreed leader. A leader now steps
  down when any member answers a newer term, a restarted member rejoins when the only leader
  it hears of is from an older term, and a node never lowers the newest term it holds.
  Found by Jepsen.
- **Warning:** a WAL address page torn by a kill loads without the item it never got, and an
  item out of bounds is left out with a warning instead of a panic; a page now writes the
  item before its header. Found by Jepsen.
- **Warning:** a member whose host does not resolve at start is no longer left out of the
  roster: it counts against the majority in elections, quorum and check-ins. Found by Jepsen.
- **Warning:** a node no longer makes a term, serves term data or takes an apply before its
  WAL is loaded; until then it answers unavailable. Found by Jepsen.
- **Warning:** a replicated insert moves the sequence of every column it fills, not only the
  key's. Found by Jepsen.
- **Low:** a write the cluster could not take right now reached the client as 08006
  (connection failure). It is now 57P03 (cannot connect now).
- **Low:** a node killed between applying a write and recording it reported a false
  divergence after its restart. Each apply is now its own prepared transaction, committed
  once its record is written, and one left in doubt is finished at startup. Found by Jepsen.
- **Low:** a catch-up that re-applied a write it held logged CLUSTER DIVERGENCE with the
  copies equal. Found by Jepsen.
- **Low:** after recon repaired a row, older writes of it pulled later were reported as
  divergent again. Recon now repairs a row only once the cluster has settled it, a blocked
  row is released only by a majority, and a pulled write whose rows a later commit all
  rewrote counts as resolved. Found by Jepsen.
- Further fixes from the same Jepsen round:
  - a cluster setting took effect on the leader before its transaction committed, and a
    setting held by a transaction a catch-up decided was never settled;
  - a failure of any party member fails the statement with a plain rollback, a prepare
    holds only when every party member prepared, and a member's record that was never
    prepared is left to the catch-up instead of closed as committed;
  - an apply, or a commit or rollback message, whose caller timed out was cut off half
    done and lost its record update; both now run to the end;
  - restart recovery: a prepared transaction left in doubt is finished by name, the WAL
    load starts from the last decided run, a partial catch-up answer is not taken as whole,
    and a Spare node pulls its gaps before it is up;
  - a member in a newer term refuses a statement of an older term (40001), a term is opened
    once under concurrent writes, the last term's tail is listed in the data version, and a
    checkout no longer closes a record still prepared;
  - a node short of an older term's last writes read itself caught up;
  - a later term's write that came before an older term's missing or undecided writes was
    reported as CLUSTER DIVERGENCE with the copies equal; it now waits for the catch-up;
  - a row could stand on three nodes of five although its write failed: a checkout poll
    marked the origin's rolled-back record committed; a checkout now closes only a commit;
  - writes stalled for good on an older term's gap no node held; the leader now voids such
    a gap when a majority of the nodes saw that term and every synced table commits on
    `all` or `half`;
  - a gap whose transaction was still in flight held writes to every synced table; it now
    holds only its own rows;
  - two leaders of one term: a node votes once per term and refuses a candidate that holds
    less data than it does, and a rollback no longer marks another transaction's committed
    record as a collision;
  - after a cold start, the loss of the leader went unnoticed during the start grace, and a
    split first vote was never retried; a cluster could also stay leaderless after restarts
    or keep a stale leader next to the new one;
  - a WAL file left without its header by a crash broke the next load; a WAL file now
    appears with its header whole, and a headerless one is moved aside at load.
- Identity and generated columns replicate: the trigger skips generated columns, an insert
  is applied with `overriding system value`, an update leaves an unchanged key out of its
  SET, and node copies (fill, reshape, stage, recon) handle both kinds.
- Any sequence a column takes its default from (not only serial and identity) is moved
  forward on the receiving nodes when a replicated insert's value is past it, without
  consuming a value and keeping the step; after a table copy every such sequence is moved
  past the copied rows.
- A table row (`A`) that `yt_setup` registers while ytserv runs takes effect without a
  restart. Before, ytserv logged "No cluster configuration found for table" on every write
  and used default table settings until restarted.
- `yt_setup`'s two-part exclude combined its parts with AND instead of OR.
- ytctl TUI read the cluster config from the wrong place. It now reads the cluster rows from
  the catalog database and the table rows (`A`) from each user database's own config table.
- `ytctl --tables public.%` took the table pattern as the config table name.

## Bundled

- rppd, the Python runtime in ytserv-py, is now MIT licensed.
- Schema Guard can take its migration scripts from a zip archive (`source_zip`), unpacked
  into a temporary directory and removed afterwards.

# YaXAHA Cluster 0.18.81

Published 2026-10-12, under the product's former name. deb `yaxaha` 0.18.81, EL9 rpm
0.18.81. ytserv 1.1.81.

The first release on record. Earlier builds were published without notes, so this file
lists what the product held at this version, and the changes and fixes of the week before
it (from 2026-10-05).

## What it holds

- Package and extension `yaxaha`, CLI `yxctl` (now `ytctl`), server `ytserv`; a deb for
  PostgreSQL 18 and an EL9 rpm.
- Consensus: leader election by terms, a WAL of subterms, two-phase commit (PREPARE /
  COMMIT PREPARED) and one-phase for a one-member party, apply in natural order, data
  versions with pulls of missed history.
- Postgres extension: the `yt_synchronize` trigger captures row changes, `yt_complete(true)`
  runs the cluster commit, `yaxaha.auto_complete` does it on a plain COMMIT, `yt_setup()`
  registers a table, `yt_info()` reports state. The setup SQL ships in the extension's
  install script.
- Configuration in the `yt_config` table by module (C cluster, N nodes, Z zones, A table
  routing and others); per-table commit rule `cluster_commit` (half, all, nodes>=N) and
  sequential consistency.
- Availability zones and shards: tables routed to zones by A rows, recon row repair by
  majority, catch-up pulls.
- Linked clusters: upper, lower and neighbor levels, a lower leader's sign-in admission, the
  az catalogue.
- Runtime node add by physical copy (pg_basebackup), Spare and retired nodes, deputies
  (Backup, Reserve).
- Embedded rppd (Python functions run on table events or etcd queue messages, cron jobs),
  embedded etcd, ClickHouse sink, MPP, LLM functions; peer stream (off by default).
- CLI with a TUI: install, server config, table registration, `--encode-table-cfg`,
  uninstall.

## New

- **Linked-cluster relay:** the lower cluster's leader carries committed rows of routed tables
  down from its upper cluster and up to it, one hop, applied as a read-only feed in source
  order. A row is taken only from an az that may write its table; the table's A row options
  `no_down` / `no_up` stop a direction. The position per source is kept in C rows
  `relay.<az>`.
- Pings carry the cluster uuid: a peer of another cluster is treated as a link, so linked
  clusters keep their own terms and leaders.
- **Runtime topology jobs** in the synced `yt_job` table: an INSERT requests a job, the leader
  approves it, one active job per table, state `cancel` cancels. Kinds: `az_create` and
  `az_delete` (a delete is refused while a routed table or a live node uses the zone),
  `move` (re-route a table: the old rule stays in force while the new holders fill, then it
  flips), `cleanup`, `noop`, `split` (a zone's members become their own linked cluster at a
  cut position) and `combine` (a cluster merges back once its relay drains). A move deletes
  no data unless it has `purge=true`, and purge deletes a row only when another node holds
  it. Group jobs are approved by the cluster's own leader or a direct upper cluster;
  participating clusters are locked all or none.
- In-doubt two-phase recovery: after a restart the origin decides its undecided
  transactions by their local outcome, and members commit or roll back prepared
  transactions left in doubt.
- **jsonb merge** for tables with `merge`, `merge_all_fields` or `merge_text`: writes to
  different paths of one row both commit; numbers under `merge_all_fields` merge as
  increments, `merge_text` columns by a 3-way line merge, arrays element by element or by
  append.
- **Join gate with operator approval:** a joining node proves its P-256 node key, waits as
  Unconfirmed in a J row and is admitted after `yxctl --skv-approve <uuid>`; approved keys
  are kept in K rows.
- `yt_info('E')` rows `state` and `cfg.<name>` (settings that differ from the defaults, URL
  passwords masked), plus `forever_spare`, `merge_refused` and `node_key`.
- An empty node catches up by filling its tables from its peers.
- Registered tables also get a TRUNCATE statement trigger.
- C setting `rppd_db`, the database that holds rppd's config.

## Changed

- Errors carry a SQLSTATE: 40001 retry (an in-flight write of the same row, a row behind on
  this node, a sequential-consistency conflict), 55409 intersecting merge (do not retry),
  55000 blocked row. An array append onto an array that grew elsewhere is refused with 55409.
- Elections after a leader loss: the designated Backup starts at once, the others later on a
  random turn (Reserve before the rest); ties go Backup, then Reserve, then the lower uuid.
  This ends split votes and a non-deputy winning.
- The node count for commit rules leaves out Spare, Paused and Unconfirmed peers.
- A replayed insert of an existing row is skipped, and a failed apply is logged as a warning.
- ytserv removes the app key variable `SECRET` from its environment at startup.

## Fixed

- A party member dropped at its statement (a timeout) kept its session and held the row lock
  for good: applies of that row stalled and the write could be lost. The origin now sends an
  abandon notice, and the member rolls back.
- An origin killed between `yt_complete(true)` and its local COMMIT lost the row while the
  party had it. At restart it re-applies its own committed writes from the WAL.
- Concurrent writers of one merge-table row on different nodes deadlocked and both timed out.
  Now a younger write never waits on an older in-flight one, and two merge writes checked in
  at the same moment can no longer both pass the conflict scan.
- A rollback after a refused prepare never reached the party, leaving a phantom commit on a
  member; a node pulling history could take a subterm still in its party phases as committed.
- Nodes that do not hold a zone-routed table missed its subterms for good, so their leader
  stayed "behind" and the cluster unwritable.
- In-flight subterms were counted as gaps, so writes were refused as "behind on this node";
  check-in issued a subterm before choosing the party, leaving holes.
- On a single-node cluster every write aborted with "Not enought working nodes".
- A node joined by physical copy missed writes made during its copy window; a node starting
  without a WAL rolls back the prepared transactions it inherited.
- Election races: two elections on one node, a Candidate stuck after a confirm, and a
  lost-leader check clearing a newly confirmed leader. A Spare node was never admitted.
- Linked clusters leaked into each other: WAL saves and pulls, term pulls, parties, recon,
  rppd, etcd and DNS now use own members only, and link callers are refused outside ping
  and sign-in. After a split, a check-in from another cluster's origin is refused.
- Moves: recon deleted rows during a widening move; a node routed itself by the cluster's az
  instead of its own; a move never flipped when the comparing node was a target; a disjoint
  move moved nothing. A combine left a participation lock behind.
- ytserv exited when one peer host did not resolve; it now skips that peer with a warning.
  A node whose own N row is missing logs an error instead of binding 127.0.0.1.
- An applied update compared a NULL column with `= NULL`; the extension missed an UPDATE that
  changed only a float, bool or unsigned column; an UPDATE of a primary key column now
  carries the old key.
- A users database's table config was not loaded; `yxctl --encode-table-cfg` dropped
  `cluster_commit`, `filter` and `db_source`; uninstall with purge removes the working
  directory.
- Party members kept the origin's transaction data (a leak); internal deadlocks on the bus
  and in a broadcast to more than ten peers; the recon frame checksum overflowed.

## Bundled

- rppd 0.2.8 to 0.2.12: cadence watch (an `rppd_cron` row with `cadence=true` expects an event
  every `cron` period; a late event posts to `watch_q`, then once to `deadline_q`); a
  non-master node forwards events to the rppd master; each queue gets its own watch.

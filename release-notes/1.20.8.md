# YT Cluster 1.20.8

Published 2026-11-02. deb `yt-cluster` 1.20 (build 1.20.8), EL9 rpm 1.20.8, tgz 1.20.8,
Docker image `dbinvent/yt:1.20.8`. ytserv 1.20.8.

## New

- **Secret rotation:** `ytctl --rotate_key=<name>` rotates a secret in the secret store.
  `--value` (or `--file`) gives the new value; without one, ytserv generates a 43-character
  URL-safe value, which ytctl prints once or writes to `--to` with mode 0600. A key that
  does not exist yet is created.
- While a secret rotates, the new value is handed out and both values are accepted. The old
  value is dropped `--discard_sec` (default 60) after the new one is first used on any
  member, and no later than `--adopt_sec` (default 3600) after the start. The leader keeps
  that time inside the secret, so a leader change keeps it. The rotation shows in
  `yt_info('X')`.
- ytserv-all: rppd functions get `SECRET.check(name, value)`, which accepts the old or the
  new value while a secret rotates.
- ytserv-all: **message bridge** inside the node's own etcd. It sends a queue or prefix to
  AMQP, MQTT or Kafka, or runs an AMQP listener. 16 node-level `bridge_*` settings configure
  it, and it is off unless they are set. Broker passwords come from the secret store by name
  (`bridge_to_secret`, `bridge_listen_password_secret`), never from a setting. The bridge
  restarts when a setting changes or its secret rotates.
- A `bridge` row in `yt_info('E')` reads `off`, `running #N`, `waiting: <why>` or
  `refused: <why>`. `yt_info('c')` masks passwords in URLs. The bridge refuses a prefix under
  `/secret/` and a listener without a login beyond localhost. The regular ytserv logs a
  warning when `bridge_*` rows are set.
- ytserv-all: rppd function health tests. A function's `test` entry point runs on deploy and
  on a schedule from `rppd_cron`, never on a normal event, and its writes roll back. A deploy
  is a NULL `test_timestamp` (in YT Cluster: after a restart, on the rppd master). New
  columns `test_level` and `test_timestamp`. A failing test is reported as `RPPD-E149`.

## Changed

- A rotating key refuses a second `--rotate_key` and `--skv put`. `--force_new` replaces the
  new value, but only while it is unused. `--rotate_key` is refused while any member runs a
  ytserv that cannot rotate (each member reports this in its ping).
- ytserv-all: rppd runs a function's events in one namespace, as a Python module runs. The
  function's own `def`s now see `DB`, `ETCD` and the file's imports, where before they
  raised NameError. State a function kept between calls through `global` in `__main__` is
  no longer kept.
- ytserv-all: rppd messages are translated into de, en, fr, ja, ru and zh, and every error
  starts with an `RPPD-Ennn` code; ytserv sets rppd's language from the node's. "Service was
  not ready" is now `RPPD-E160`, and PostgreSQL users get `RPPD-E122 not started: ...`
  instead of `Internal error "not a master"`.

## Fixed

- **Warning:** ytserv-all - two rppd cron rows due in the same minute overwrote each other.
  Both now run.
- A refused secret store write gives PostgreSQL's reason instead of "db error".

## Bundled

- etcds 0.23.0 (was 0.22.1). Fixes for the embedded etcd:
  - **Warning:** a watch message carries a response header; Go etcd clients such as etcdctl
    3.4 crashed on the first event;
  - **Warning:** a race that could leave a new watch never told of changes is gone;
  - **Low:** a client that has gone no longer leaves its watches registered;
  - `localhost` binds to IPv4 first where `::1 localhost` comes first.
- etcds 0.23.0 bridge fixes:
  - **Warning:** `amqps://` now starts TLS (brokers dropped it with "early eof");
  - **Warning:** a queue or prefix the node keeps local is not bridged out;
  - **Warning:** a `?` in a password no longer breaks the URL or shows in an error;
  - **Low:** AMQP passwords are percent-decoded;
  - `?ca=` works for amqps and mqtts.

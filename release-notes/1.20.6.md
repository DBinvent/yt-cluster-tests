# YT Cluster 1.20.6

Published 2026-10-31. deb `yt-cluster` 1.20 (build 1.20.6), EL9 rpm 1.20.6, tgz 1.20.6,
Docker image `dbinvent/yt:1.20.6`. ytserv 1.20.6.

## New

- A one-column exact unique key beside the primary key is probed across the cluster on
  insert: 23505 when a duplicate is committed elsewhere, 40001 when one is in flight. The
  extension also reports CREATE INDEX (`yt_ddl_idx`).
- **DocumentDB:** BSON columns (`documentdb_core.bson`) replicate and merge. Merge tables
  merge documents path by path (3-way), and document keys compare by bytes. Feature
  `documentdb` is in the default ytserv; the DocumentDB gateway is not bundled.
- Table option `merge_async`, off by default (implies merge, under `cluster_commit`
  nodes>=1): an update commits locally first and checks in after, coalesced per row and
  merged by path on the members.
- A Warning alert (source recon) when rows sit below the floor on some members, resolved once
  all members answered.
- In repair mode, recon asks a member that holds the rows to queue again what another member
  lost.
- Members report their ytserv version in pings, kept across restarts.

## Changed

- `ytserv-py` is now `ytserv-all`: deb only, built for the host glibc; no longer in the
  glibc 2.35, 2.34 and musl tarballs or the EL9 rpm. `ytctl --all` selects it (`--python`
  stays an alias), and the package moves existing units over (`ytctl --upgrade-units`).
- `ytctl --copy`: the source writes its position, holes included, into a temporary
  `copy.<target>` config row in one transaction before the base backup. The copy seeds from
  it, pulls the holes and what follows, and never applies again what it holds. The seed
  survives a restart, the `least` row only grows, and `yt_info('copy_position')` gives a
  node's position. This fixes a copy seen as behind in the terms before its position,
  subterms the backup held being applied again, and holes left by a long transaction.
- Replicated transactions run with fixed DateStyle, IntervalStyle, bytea_output and
  extra_float_digits, so values compare the same on every node.
- A node asks for one lease at a time, waits 250 ms after a refusal and logs refusals at
  most every 30 s; a lease run is noted at the grant.
- rppd is not started on a spare node that has peers.
- Docker image `dbinvent/yt` ships gosu 1.20 built with Go 1.27.3, clearing 1 critical and
  25 high CVEs of the old gosu.

## Fixed

- **Severe:** a DELETE on a table with no primary key replicated as an unqualified
  `delete from t` and emptied the table on the other members. A keyless row is now matched
  by its whole old row, one row only, and keyless changes go only to members whose ytserv
  can take them.
- **Severe:** writes made inside a subtransaction (a savepoint, and every DocumentDB write)
  were tracked under the subtransaction id and never completed in the cluster. The trigger
  and `yt_complete` now use the top transaction id.
- **Severe:** rows tied by a foreign key, either way and across partitions, are now checked
  together.
- **Severe:** a refused write fails with SQLSTATE 40001 (retry) instead of a data-loss error,
  and the refused rows are pulled in the background.
- **Severe:** an INSERT on a composite or inexact unique key is checked across the cluster
  by its canonical key.
- **Warning:** a lease is refused where its rows are tied to others.
- A check-in compared only the terms its origin names; it now also walks every newer term
  and the older terms the origin lacks.
- A flood on the internal bus could stall every node in DataLoading. Data-version rebuilds
  are coalesced, and checkouts are sent only when owed.
- A gap was taken as resolved by a later write to other paths of the same document, which
  lost writes. Resolution is now path-aware, and merge tables keep deferring.
- A database could be dropped from the registry when members did not answer, which lost
  writes.
- `ytctl --bootstrap` uses russh 0.65 directly (async-ssh2-tokio dropped), clearing
  CVE-2026-102823 (high); ytserv's dependencies were updated for cargo audit.

## Bundled

- etcds 0.22.1: a queue whose consumer is down is handled after `queue_down_timeout`
  (default 300 s); a registry version signal; a promoted node takes the whole registry; a
  slow watcher is canceled (ETCD-E085).
- rppd on etcds 0.22; rppd watches an external etcd again after it drops.
- diff-doc-rs 1.0.1 with BSON, used by merge tables.

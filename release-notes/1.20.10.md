# YT Cluster 1.20.10

Published 2026-11-04. deb `yt-cluster` 1.20 (build 1.20.10), EL9 rpm 1.20.10, tgz 1.20.10,
Docker image `dbinvent/yt:1.20.10`. ytserv 1.20.10.

## New

- **Schema migrations rolled across the cluster** by the sge worker, off by default. An
  operator inserts a `yt:roll` row with a target version into the history table (setting
  `sge_history`, default `public.sge_history`); its trigger starts the worker on any node.
  The origin applies first, then the followers, the leader last. Each node runs sge
  in-process on its own database.
- Worker row states: `yt:pending`, `yt:done`, `yt:failed <reason>`,
  `yt:failed halted <node>: <reason>` and `yt:abandoned`.
  - A failure halts the roll and blocks other versions. To retry, set the failed row back
    to `yt:pending`.
  - A node away for 30 s is skipped, then returned to later.
  - A leader takes over a roll whose worker died, checked every 15 s.
  - `sge_all_at_once` (`*` or a table list) applies on all nodes at once.
- Scripts come from `source_zip`, `source_git` or `source_dir`, in that order; a folder is
  zipped. ytserv ships the archive between nodes and refuses non-members. Every node's row
  records `script_tag`, the md5 `checksum` and the `size`. A git roll pins the whole commit.
- The roll's outcome (`finished` or `failed`, and the `commit` it deployed) goes as JSON to
  the etcd queue named in `sge_notify_queue`; the bridge can forward it to an outside CI.
  Status in `yt_info('E')` row `sge`. The `sge_*` settings are cluster scope, and a bad value
  is refused at its statement.
- `yt_info('E')` row `etcd_peers` shows the etcd peers not online and how many were brought
  back (see Fixed).
- ytserv-all: column `rppd_function.required_version` (`V`, `R`, `B` or NULL) says which
  schema version a deploy must meet; rppd adds it at start and stores it.

## Changed

- ytctl refuses RSA SSH keys and says why: use an ed25519 or ECDSA key. The `rsa` crate
  (RUSTSEC-2023-0071) is gone from the build.
- The error "Service was not ready" is translated (en, ru).
- A failed connection while applying config shows the database's message
  (`apply connect: ...`).
- ytserv-all: rppd reloads `rppd_function`, `rppd_cron` and `rppd_config` in full once a
  minute, so function code changes take effect without a restart. Its database sessions set
  `lock_timeout = 5s`.

## Fixed

- **Warning:** a node's first write after it joined could be refused with "this node lacks
  T.S, a write the leader no longer holds to compare this one with": the leader had trimmed
  writes the joining node still needed. A joining node that answers now holds the leader's
  cache floor back, as a follower does.
- An etcd peer that missed one write (paused or slow) got no more of that node's writes,
  queue messages included, until it was promoted. ytserv now promotes it back once it
  answers, checking every 5 s, and logs a warning.
- ytserv-all: rppd cron reloads - an unchanged job keeps its due time (a reload used to lose
  a firing); a failed job stays scheduled with its error; only a bad cron expression stops
  a job; optional function columns that cannot be read are an error instead of defaults.

## Bundled

- etcds 0.24.0 (was 0.23.0): an HTTP/HTTPS bridge target, one POST per message with a Basic
  or Bearer login, so ytserv-all's `bridge_to` can be an `https://` URL; bridge messages in
  six languages; the official etcd v3.7.3 protos, still wire compatible (`RangeStream`
  answers in one chunk, `Downgrade` and `AuthStatus` answer unimplemented); a stopped bridge
  listener no longer leaves tasks running.
- sge: the history table's lock now locks (it locked nothing before, standalone too); in a
  cluster each script's history row commits as the script ends; psql runs as application
  `sge-roll`, and a run first ends such sessions a killed run left; a `source_git_ref`
  starting with `-` is refused; a commit on a branch other than the default is found.
